# Pixiko Android 客户端

**v1.4.0 起新增**（**v1.5.0 起默认打开新的手机端界面 `/m`**）。作者：loriko（deloriko@outlook.com）。

把网页控制台**搬到手机上**的一个 Android app：包名 `cn.szu.bot.app`，版本 **1.6.0**（`versionCode 160`）。

---

## 一、这是什么

**原生外壳 + WebView 承载机器人发出来的网页。**

app 里显示的就是**你机器人发出来的那套网页**：**v1.5.0 起默认打开的是新的手机端界面 `/m`**
（`webui/m/`，另一套从零写的手机优先页面）。**切换界面是双向但入口不同**：在 `/m` 里走网页的
「**更多 → 完整控制台（网页版）**」，在完整控制台 `/` 里走 `⋮` 菜单的「切换到手机界面（`/m`）」；
选择会被记住（见下面「App 级入口搬到网页里」）。所以：

- **网页有什么，app 里就有什么**——出图 / 提示词 / 样式 / LoRA / 提示词集 / 聊天配置 / 系统 /
  首次配置 / 日志 / 回执 / 帮助（**11 个栏目**）+ **常驻右侧的对话栏**，共 **13 栏**，
  按钮、表单、面板一个都不少（手机端界面走的是**同一套 `/api/*`**，所以功能一个不少）；
- **以后网页更新，app 自动跟着更新**——不需要重新出包（app 每次都从你填的那台机器人加载页面）。

**手机端界面 `/m` 是什么**：顶部 app bar + 底部 **5 个 tab（对话 / 出图 / 回执 / 样式 / 更多）**，
内容用卡片列表、多动作走底部动作面板、触摸目标 ≥44px、每屏有加载 / 空 / 错误三态，
用 hash 路由因此**返回键可用**；**完整控制台照旧在 `/`**，两套页面互相独立。
**v1.5.1 起 `/m` 的排版与可读性整体重做**：一套全站字号 / 控件规格（正文 15px、可点控件 ≥44px、
输入框 16px 防 iOS 聚焦缩放），**参数一律完整折行不再省略**（回执命令原文与摘要、样式名与分类名、
底模说明、提示词词条、LoRA 名、日志行都完整显示；原生 `<select>` 关闭态必然单行截断，
所以下拉下面补一行**完整值行**）。
**v1.5.2 起 `/m` 的图集 / 对话气泡 / 进度格走服务端缩略图（`w=320`）**，不再拉 2.5 MB 的全尺寸原图；
**查看器、长按菜单里的保存 / 分享、复制图片地址仍然拿原图**（`/api/image` 不带 `w`）。
同一版还修掉了「存档里的 `file:///…` 图片路径被拼成 400 地址、整屏图出不来」这个 bug，
回执详情改增量渲染、取不到的图显示「图取不到」占位。
**v1.5.3 起对话里「执行指令：…」这类系统行也从居中改成靠左**（与机器人回复同侧，
样式像一行日志：无气泡底、左侧一条细线、灰字小一号）；**桌面控制台的 `.msg.sys` 仍是居中**。
**v1.6.0 起 `/m` 又多了这些**：**出图屏与系统 / 更多屏里的 VAE 冲突横幅**（WARN 黄条 /
**BLOCK 红条 + 一键修复**，与桌面控制台同一套判定）；**图片按真实比例显示**（图集与出图屏不再把非方图
压成方块），"新出的图"不再闪空占位（改增量同步、不整块重建）；**LoRA 屏能直接搜 Civitai**
（本地 / Civitai 分段、滚到底翻页、下载可暂停 / 取消）。
在**电脑浏览器**里直接开 `/m` 时，满足「顶层文档 + 视口宽 `> 560px` + 主指针不是触摸
（`pointer: coarse` 为假）」才会套一个 **390×844** 的机身框（缩放按视口高度自动算；**v1.5.1 起
下限 70%**，且**可用高不足约 591px / `innerHeight` 不足约 687px 时干脆不套框、直接铺满**，
框下有小字标注）；**其余一律铺满** —— 真机（含平板竖屏 768×1024、手机横屏 844×390）都不套框，
所以把手机横过来不会缩成中间一条窄条。

**App 级入口搬到网页里（v1.5.0 起）**：**`/m` 下原生 ActionBar 是隐藏的**
（让位给网页自带的 app bar，见 `MainActivity.applyActionBarVisibility()`），所以 **`⋮` 菜单在
手机界面里点不到**；那几项被移到网页的「**更多 → App**」分组：**服务器设置 / 清空网页缓存 /
清除登录状态 / 在浏览器打开**（这 4 行**只有存在原生桥时才建**，用纯浏览器打开 `/m` 时连 DOM 都不建），
外加**常显**的一行「**完整控制台（网页版）**」→ 同窗口跳 `/`。

在此之上，原生外壳补了 **6 类网页做不到或做不好的能力**：

| 能力 | 说明 |
|---|---|
| **服务器管理** | 填地址 + 访问令牌即可连上；可保存**多台服务器**并一键切换 |
| **地址简写** | 填 `192.168.1.5:8787` 这种就行，app 会自动补 `http://` 与默认端口 **8787** |
| **测试连接** | 先打 `/healthz`，再打**带令牌的** `/api/status`，因此能**区分「连不上」和「令牌不对」** |
| **局域网扫描** | 按当前 Wi-Fi 网段扫 `:8787` 上的机器人，**找到就一键填入**地址 |
| **令牌自动注入** | 不用在网页的锁屏页里再敲一次令牌 |
| **图片保存 / 分享** | 在网页里**长按图片**即可**存进手机相册**（`Pictures/Pixiko`）或**分享出去** |
| **下拉刷新 / 进度条 / 原生错误页** | 连不上时不是一片白，而是列出可能原因并给「重试 / 去设置 / 用浏览器打开」 |

另外还有：**返回键行为**（回退 → 回首页 → 再按一次退出）、**屏幕常亮**开关、
**清网页缓存 / 清登录状态**、「在浏览器打开」、**关于**页；**文件选择、下载、新窗口、图片查看器**
都做了原生适配。**在 `/m` 里，这几项里的服务器设置 / 清空网页缓存 / 清除登录状态 / 在浏览器打开
走网页「更多 → App」分组**（`⋮` 菜单在 `/m` 下点不到，理由见上）。

**完整控制台 `/` 不用另做界面**：控制台本身就是**响应式的**（**≤1000px 变单列堆叠**），
**390×844 的手机宽度已在真机浏览器里验收过**（无横向滚动、右侧对话栏在下方堆叠、结构完整），
所以 v1.4.0 起 app 里直接复用同一套网页。**v1.5.0 起默认改走上面那套另写的手机端界面 `/m`**；
**v1.5.0 新增的 `/m` 与 v1.5.1 的排版重做都没有做虚拟化 / 模拟器验证**
（v1.5.1 的验收是 headless Chrome + CDP 的触摸与软键盘模拟）。

## 二、三步用起来

1. **手机和电脑连同一个 Wi-Fi**（同一个局域网/网段）。
2. 打开 app，填两样东西：
   - **地址**：`电脑的局域网 IP:8787`（例如 `192.168.1.5:8787`；**只填 IP 也行**，端口默认就是 8787），
     或点「**扫描局域网**」自动找；
   - **访问令牌**：在**电脑**的 `config.json` 里，字段是 **`webui.access_token`**
     （首次启动若为空，机器人会自动生成一个并写回 `config.json`，日志里有）。
3. 点连接，**进去看到的默认是新的手机端界面 `/m`**；想回完整控制台，用网页里的
   「**更多 → 完整控制台（网页版）**」（`/m` 下原生 `⋮` 菜单是收起的，切过就记住）；
   **长按图片**可以存进手机相册 `Pictures/Pixiko`，或分享出去。

> 想确认地址和令牌都对，用 app 里的「**测试连接**」——它会分别报「连不上」还是「令牌不对」。

## 三、（可选）不装 APK 看效果：网页预览

**不用装 APK，也能在浏览器里跑一遍这个 Android 外壳**：机器人自己伺服一页预览
**`http://<电脑地址>:8787/android`**（用户原话是「我想让你用 webview 在网页上跑一个预览版」）。

- **怎么打开**：控制台**每一页页脚**都有「**安卓外观预览**」链接（`href="/android"`）；
  也可以直接在浏览器里敲 **`http://<电脑地址>:8787/android`**（在机器人那台机器上也可以先试 `127.0.0.1:8787`）。
- **能演什么**：
  - **app 外壳**：顶部 `Pixiko` 标题栏 + 进度条 + `⋮` 菜单（**与真机一致的 9 项**：刷新 / 回到首页 /
    切换服务器 / 服务器设置 / 在浏览器打开 / 屏幕常亮 / 清空网页缓存 / 清除登录状态 / 关于）；
  - **手机机身外框**：设备预设 **手机 390×844（默认）/ 大屏手机 430×932 / 平板 768×1024 / 自适应**，
    缩放 **50–100%**，另有「**旋转**」（844×390）；
  - **中间是同一套真网页**（同源 iframe）：**v1.5.0 起默认装的是手机端界面 `/m`**（与真机默认一致）。
    想切到完整控制台：**点 `/m` 页面里的「更多 → 完整控制台（网页版）」**（与真机同一条路），
    或者用**预览页自己的 `⋮` 菜单第 3 项**在「手机界面 `/m` / 完整控制台 `/`」之间切——
    那是**预览页模拟外壳**的菜单，与真机行为一致；切到完整控制台时是
    **11 个栏目 + 常驻对话栏一个不少**，手机宽度下网页自己变单列堆叠；
  - **服务器设置屏**（地址 / 令牌 / 测试连接 / 保存 / 多服务器列表）：「测试连接」**同样能区分
    「连不上」与「令牌不对」**（与真机同一个判据）；
  - **长按 / 右键图片弹 app 的原生菜单**（保存到相册 / 分享… / 在新标签打开 / 取消），以及打不开
    控制台时的**原生错误页**（列出 4 条可能原因 + 重试 / 去设置 / 用浏览器打开）。
- **和真机的差别（预览页里会如实提示）**：「保存到相册」在浏览器里**等价于下载**（网页写不了手机相册）；
  **没有局域网扫描**（同源策略不允许网页去探内网端口，页面会明确说明，真机才有）；**没有后台通知**；
  **屏幕常亮**依赖浏览器的 Wake Lock API；**「分享」**在部分浏览器退化为复制地址；
  **只在同一台机器人上同源**时才能注入令牌与长按菜单（跨源打开会提示不可用）。
- **预览页与 APK 用的是同一段长按脚本（逐字相同）**：预览页往 iframe 里注入的脚本取自 app 的
  `NativeHook.hookScript()`，**1834 字节、逐字相同**（所以改了 `NativeHook.java` 就要同步改预览页）。

## 四、连不上怎么办？

真机上最常见的就是这一步。按下面顺序排查，基本都能解决。

**1. 地址和端口对不对**

- 电脑的局域网地址和机器人端口要对上。例如这台机器上是
  **`172.30.204.50`**（以太网，`/24`）、机器人监听 **`8787`**（`webui.host = 0.0.0.0`），
  那 app 里就填 **`172.30.204.50:8787`**（或点「扫描局域网」找）。

**2. 手机必须和电脑在同一个网段**

- 例如电脑是 `172.30.204.x`，手机也得在 `172.30.204.x`。
- **校园网 / 公共 Wi-Fi 常做客户端隔离**（同一 Wi-Fi 下设备之间互相看不见），
  这种网络里手机就是连不上电脑——用下面的第 4 条（USB）兜底。

**3. Windows 防火墙默认会挡住入站的 8787**

非管理员身份加规则会失败（`Access is denied`），所以**用管理员权限的 PowerShell 跑一次**
（只需一次）：

```powershell
New-NetFirewallRule -DisplayName 'Pixiko 控制台 (TCP 8787)' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8787 -Profile Any
```

不想要了可以删掉：

```powershell
Remove-NetFirewallRule -DisplayName 'Pixiko 控制台 (TCP 8787)'
```

**4. USB 兜底（推荐给校园网 / 隔离网络）**

手机 USB 连上电脑、打开 **USB 调试**，然后在电脑上跑：

```powershell
adb reverse tcp:8787 tcp:8787
```

然后把 app 里的地址填成 **`127.0.0.1:8787`**——手机上的 `localhost:8787` 会被转发到电脑的机器人，
**完全不依赖 Wi-Fi 与防火墙**。

- `adb reverse` **每次重插 USB 后要重跑一次**；
- `adb` 在 **Android SDK 的 `platform-tools`** 里。

**5. 排查清单（照着走一遍）**

1. 地址 / 端口对不对？
2. 电脑自己的浏览器能不能打开 `http://127.0.0.1:8787`？
3. 手机浏览器能不能打开 `http://<电脑IP>:8787`？（**打不开就是防火墙或网段问题**）
4. 令牌对不对？（app 里「测试连接」会区分「连不上」与「令牌不对」）

## 五、怎么构建 APK

> 只是**想用 app**的话不需要看这一节：直接用构建好的 APK 装上就行（见下面「装到手机」）。
> 这一节讲的是**自己从源码构建**。

### 需要的工具链

| 组件 | 要求 |
|---|---|
| **JDK** | **JDK 21**（脚本用 `-JdkHome` 指定，比如 Android Studio 自带的 JBR） |
| **Android SDK** | `platform-tools`、`platforms;android-34`、`build-tools;34.0.0` |
| **Gradle** | **8.9 – 8.14**（与 AGP 8.x / `compileSdk 34` 匹配） |

工程本身的参数：Java、Android Gradle Plugin **8.x**（根 `build.gradle` 里是 **8.6.1**）、
`compileSdk 34`、`minSdk 26`、`applicationId` **`cn.szu.bot.app`**、版本 **1.6.0**（`versionCode 160`）。

### 一键构建

仓库里带了一个脚本 `android/build-apk.ps1`，它会用你指定的 JDK 与 Android SDK 跑
`assembleDebug`，并把 APK **复制到输出目录** `F:\Bot\android\dist\`：

```powershell
powershell -File android\build-apk.ps1 -SdkRoot <Android SDK 路径> -JdkHome <JDK 21 路径>
```

- `-SdkRoot`：Android SDK 根目录（里面应有 `platform-tools\`、`platforms\android-34\`、
  `build-tools\34.0.0\`）；
- `-JdkHome`：**JDK 21** 的根目录；
- 在**仓库根目录**执行（或者把 `android\build-apk.ps1` 换成实际路径）。

### 构建时自动烧进「本机局域网地址」当测试默认值

每次跑 `build-apk.ps1`，它都会**先探测本机局域网 IP**，把 **`<IP>:<端口>`** 通过 Gradle 属性
`-PpixikoDefaultHost=…` 交给 `app/build.gradle`，后者把它变成 **`BuildConfig.PIXIKO_DEFAULT_HOST`**
（**源码里没有任何写死的 IP**，只有这一条路）。App **首次运行**（一台服务器都还没保存过）打开
「服务器设置」时，会把这个地址**预填**到地址框里，下面还有一行小字
「↑ 这是构建时烧进去的测试地址（…），可直接改成别的；令牌仍要自己填」——
装上就能直接点「测试连接 / 保存」，不用手输 IP。

| 参数 | 作用 |
|---|---|
| **（都不给）** | 自动探测：读 `config.json` 的 `webui.port`（读不到用 **8787**）＋ 自己挑一张网卡的 IPv4 |
| **`-DefaultHost 192.168.1.5:8787`** | 显式指定，跳过探测（只写 `192.168.1.5` 也行，缺端口按 `webui.port` 补） |
| **`-NoDefaultHost`** | 完全不注入：`BuildConfig.PIXIKO_DEFAULT_HOST` 是**空串**，行为与没有这个机制时一致 |
| **`-ConfigPath D:\x\config.json`** | 换个 `config.json` 读端口（**只读，绝不写**） |

探测规则（这台机器有 VPN / 虚拟网卡，所以必须排除干净）：

- **排除网段**：`127.*`、`169.254.*`（APIPA）、`0.*`、`224.*`、`240.*`、`198.18.*`
  （代理软件的 fake-IP 段）、`100.64.*`（CGNAT）、`192.0.2.*` / `198.51.100.*` / `203.0.113.*`（保留段）；
- **排除虚拟网卡**（对「网卡名 + 网卡描述」做关键字匹配）：VirtualBox / VMware / Hyper-V / WSL /
  Docker / TAP / TUN / Wintun / WireGuard / OpenVPN / Tailscale / ZeroTier / 蓝牙 等；
- **排序取第一名**：能 HTTP 应答机器人（`<IP>:<端口>` 的 `/healthz`）＞ 有 IPv4 默认路由 ＞ RFC1918 私网 ＞
  接口度量（`InterfaceMetric + RouteMetric`）更小；最后对第一名**真发一次 `GET /healthz`**
  （即「机器人真的在这张网卡上可达」，和 app 里「测试连接」的第一步是同一个判据）。
  刻意**不用**「TCP 能连上」当验证：这台机器的 TUN 代理会对任意远端 IP 假握手
  （实测连 `10.1.2.3:9999`、`8.8.8.8:9999` 都报「连上了」），那种验证等于没验证；
- **探测失败不会让构建失败**：要么**不注入** + 打印一句人话警告，要么照常注入但明确警告
  「`/healthz` 连不上这个地址，可能是机器人没在跑 / 防火墙挡着，可用 `-DefaultHost` 指定别的」。

构建结束时脚本会把**本次烧进去的地址**清楚地打出来（还有生成的那一行 `BuildConfig.java`）：

```
  默认地址 : 172.30.204.50:8787
             ↑ 本次烧进 APK 的测试默认服务器地址（BuildConfig.PIXIKO_DEFAULT_HOST）
  BuildConfig: public static final String PIXIKO_DEFAULT_HOST = "172.30.204.50:8787";
```

几条边界，别误会：

- **只是预填**：不自动连接、不写 SharedPreferences、不设为当前服务器，要用户自己点「保存」；
- **不碰令牌**：`config.json → webui.access_token` 仍然要自己抄进 app（预填的**只有地址**）；
- **不覆盖用户数据**：只要**已经保存过服务器**（或地址框里已经有内容），这个默认值就完全不出现；
- **`-NoDefaultHost` 构建出来的包**：常量是空串、那行小字也不出现，与加这个机制之前**行为一致**
  （APK 字节数当然还是会随其它源码/文档改动变化）。

### 产物在哪

Gradle 的原始产物：

```
android\app\build\outputs\apk\debug\app-debug.apk
```

脚本会把它复制到输出目录 **`F:\Bot\android\dist\`**，复制后的产物名是
**`pixiko-<版本>-<构建类型>.apk`**，也就是本版的 **`pixiko-1.6.0-debug.apk`**
（版本号取自 `app/build.gradle` 的 `versionName`；本版客户端 **1.6.0 / versionCode 160**）。
**本版重新出包了**（外壳与构建脚本都有改动）；`android/dist/` 里那份 `pixiko-1.6.0-debug.apk`
是**本机测试用**的（带了构建时烧入的局域网地址），**发布附件要用 `-NoDefaultHost` 构建的那一份**
（不含任何本机私网地址，见上一节「构建时烧入局域网地址」）。
**网页（含 `/m`）不在 APK 里**，所以**只改网页时不需要重新出包**——v1.5.1 / v1.5.2 / v1.5.3
就都没有重新出包。

> **每版发行必做**：安卓版**不是可选项**——每次发行都要跟着出一份 `versionName` ＝**本次发行号**的 APK
> （`-NoDefaultHost` 构建、给出字节数与 sha256）；产物清单与发版前校验的完整规则见
> [`../RELEASE.md`](../RELEASE.md) 的「**发行清单（每版必做）**」。

> 上面提到的字节数与哈希只对应**当时构建的那一份**；APK 里**打进了** `app/src/main/assets/DESIGN.md`
> （外壳设计说明，随包分发），所以**改了这份文档再重新构建，字节与哈希都会变**——这是预期的，
> 不是构建不可复现。

### 装到手机

两种方式，任选一种：

1. **USB（`adb install`）**：

   ```powershell
   adb install -r android\app\build\outputs\apk\debug\app-debug.apk
   ```

2. **直接拷进手机**：把 APK 复制到手机里（数据线 / 聊天工具传文件都行），在手机上点它安装。

> 这是 **debug 包，由 debug 密钥签名**，不是正式发布签名。Android 会要求你允许
> 「**安装未知来源应用**」（各机型路径不同，一般在「设置 → 应用 → 特殊权限」里）。

## 六、安全与隐私

- **局域网 http 明文传输**：app 连机器人走的是 `http://`（`usesCleartextTraffic`），
  **同网段的人有办法看到内容**——所以**只建议在家里或可信局域网用**。
- **令牌是明文存的**：访问令牌保存在 **app 私有目录**的 `SharedPreferences` 里，**没有加密**。
  手机被 root、或装了能读私有目录的工具，令牌就可能被读出来。
- **app 不向任何第三方服务器发数据**：它只连**你自己填的那台机器人**。
- 想少一分风险：**别把 8787 直接暴露到公网**，用完可以在路由器/防火墙上关掉。

## 七、已知限制

1. **没有后台推送**：机器人来了新的**回执**，app 不会弹通知，得**自己打开 app 看**。
2. **v1.4.0 时不做手机端专属界面**：那时用的是**响应式网页**本身，没有为手机重画一套面板。
   **v1.5.0 起另写了手机端界面 `/m` 并设为 app 默认页**，这一条不再适用。
3. **平板 / 横屏能跑，但没专门打磨**：能用，只是排版没针对大屏横屏优化过。
4. **「在浏览器打开」是排查用的**：网页端的这个入口主要是**对比排查**——
   同一地址在手机浏览器里能不能开，能开就说明网络通、问题在 app 侧。
